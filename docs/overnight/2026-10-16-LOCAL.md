## 1. Signing on the Mac (once per Mac)

1. Import the "Useful Voice Release" `.p12` from the password manager. Never create a new
   certificate: a new one resets every user's Accessibility and Microphone grants.
   ```sh
   ./scripts/setup-signing.sh        # prints the import command if the identity is missing
   security import <file.p12> -k "$HOME/Library/Keychains/login.keychain-db" \
       -T /usr/bin/codesign -T /usr/bin/security
   ./scripts/setup-signing.sh        # expect exit 0
   ```
2. `make install`. It runs `make bundle`, copies the app into /Applications and launches it. The first
   run shows one codesign prompt: click Always Allow. Expect `/Applications/Useful Voice.app`, signed.
3. Launch it. The rename from Sadaa needs one Accessibility and Microphone re-grant (the "Accessibility
   is off" banner shows until it's done). If #52 is merged, first run opens for a renamed user whose
   grants are missing; check that it does, and that a login launch does not open a window.
   #52 waits for your review (migration). Before merging it, on a Mac that still has `Sadaa/` data:
   ```sh
   scripts/e2e-identity-migration.sh dist/UsefulVoice.app "$HOME/Library/Application Support/Sadaa" verify/migration
   ```
   It works on a copy and a dummy Keychain item, never your real ones. Expect a counts-only report
   with every check passing.

## 2. Real apps on macOS

Pass means all of: the text lands once, in the field that had focus at the hotkey press; the
format fits the app (below); nothing is pasted anywhere else; when the landing isn't proven the text
is on the clipboard and in History with a "Copied" notice. Use a short test sentence with a filler
("um, so we should ship it on Monday") and one with a greeting and sign-off for email.

| App | Category | Expect |
|---|---|---|
| Gmail in Chrome (compose body) | Email (from the page address) | Greeting on its own line, paragraphs, sign-off with your name if set in Settings > Apps. Filler removed. If it formats as Other, Chrome didn't expose the page address (the app doesn't ask it to); note it, and try Safari. |
| Apple Mail | Email | Same as Gmail. |
| Slack | Work chat | One line, casual, no sign-off. Auto-send off by default: nothing is sent. Turn on "Send with Return" for Work chat, dictate, and the message is sent once. |
| WhatsApp | Personal chat | Casual by default: no full stop after a one-sentence message. Switch Personal chat to Very casual in Settings > Apps: it also lowercases. |
| Claude Code in Terminal | Coding (Terminal is Coding) | File names and paths kept as written ("app dot ts" -> `app.ts`), no prose capitalisation of commands. Text with a line break is copied, never typed (it would run a command). |
| Cursor | Coding | Same as Terminal. "tag index dot ts" gives `@index.ts`; "at index dot ts" does too, because the file name looks like code; "at Monday" stays words. |
| Notion (app or web) | Docs and notes | Formal, paragraphs, no greeting. |
| App switch mid-transcription | any | Press the hotkey in Slack, switch to Notes while it transcribes. Expect a copy-only "Copied" notice, nothing pasted into Notes, text in History. |

Hotkey with no field focused (click the Dictations list, then press): copied only. Repeat with the search field focused: it lands there. This is the responder-chain check CI couldn't run. |

is back on the clipboard after a proven paste; with it off the dictation stays on the clipboard. After
a paste that couldn't be proven, the dictation stays on the clipboard either way.

## 3. AI cleanup memory and speed (S1-mini, hidden flag)

Rules-only cleanup ships on. S1-mini stays behind a hidden flag because it still dropped spoken words
in the eval (`evals/results/2026-10-16-cleanup.md`). It needs at least 7 GiB of RAM reported, runs on
English dictations only, has a 1.5 s deadline and unloads after 60 s idle. The first dictation after
launch or an idle unload gets the rules text while the model loads; later ones use it.

macOS (only once #54 is merged; today every cleanup misses the deadline on CI's Mac, 6.8 to 14.0 s):
```sh
defaults write ai.useful.voice uvCleanupModel -bool YES   # or launch with UV_CLEANUP_MODEL=1
```
Relaunch. The app downloads the pinned weights (about 484 MB, SHA-256 checked) into the Whisper
models folder. Then check, with Activity Monitor open:
- Ten English dictations with other apps open: no dictation waits on the model; memory falls back
  about 60 s after the last one. Note whether any cleaned text goes beyond the rules (fillers and
  stutters only): on CI's Mac it never did, because every call missed the 1.5 s deadline.
- Quit the app while the first load is still running (dictate once right after launch, quit at
  once): it must quit cleanly, no crash report.
- A local Whisper dictation right after an S1-mini cleanup transcribes normally (both share ggml; CI
  proved it once with a `say` clip).
- Settings shows "AI cleanup: S1-mini by Superwhisper" with the flag on, and nothing with it off.
- After `make bundle` on #54's branch, check the signature with the second framework inside:
  `codesign --verify --deep --strict --verbose=2 dist/UsefulVoice.app` passes, and
  `codesign -d -r- dist/UsefulVoice.app` shows the same designated requirement as main's build
  (identifier `ai.useful.voice` and the "Useful Voice Release" certificate). `Contents/Resources`
  holds `THIRD_PARTY_NOTICES.md`, `LICENSE` and `licenses/`. Once #44 and #54 are both merged, the
  "Release dry run" CI job builds a whole release with `llama.framework` inside; check it's green.
- Turn it off again: `defaults delete ai.useful.voice uvCleanupModel`.

Windows (merged in #56): the app has no download step yet, so place the weights by hand.
```powershell
$dir = "$env:APPDATA\Useful Voice\models"; New-Item -ItemType Directory -Force $dir
curl.exe -L -o "$dir\s1-mini-q4_k_m.gguf" https://huggingface.co/superwhisper/s1-mini-GGUF/resolve/34add00a48a2e5d24e5a4ee5405a99620a3a240c/s1-mini-q4_k_m.gguf
(Get-FileHash "$dir\s1-mini-q4_k_m.gguf").Hash   # expect 3B41EBE2502CBD03E811D5D16B022F5AB551EDA58D62597D152F89535003C634
& "<install dir>\Useful Voice.exe" --cleanup-model      # or set UV_CLEANUP_MODEL=1
```
Same checks in Task Manager: no dictation waits, memory falls back after 60 s idle, the credit shows
in Settings only with the flag. Under heavy CPU load the model misses the deadline and its worker is
restarted; the dictation must still arrive at once with the rules text.
