# English cleanup: rules, then a small local model?

Date: 2026-10-16 (runs on 2026-10-15 UTC). Branch: `feat/cleanup-rules-evals`.

## Question

Deepgram formats, it does not clean up. The cleanup order is: vocabulary, deterministic rules
(fillers and stutters), a small local model, then the user's own rules. Is a local model worth
shipping on top of the rules, and which one? The bar the owner set: ship the best option that
does not lose content more often than rules-only. If no model beats rules-only, ship rules-only
with the model behind a hidden flag.

SpeakoFlow's model card reports S1-mini damaging content on 55.3% of its (private) cases. This
suite settles that for our pipeline.

## Answer

**Ship rules + S1-mini (Q4_K_M) + `CleanupGuard`.** It is the only model option that lost no
content: 0 of 188 cases, the same as rules-only. It lifts edit accuracy from 52% to 94% (the
self-corrections, spoken numbers, emails and file paths the rules cannot touch: 0% to 88%).
The price is restraint: it changed 8 of 88 already-clean texts (91% restraint against 100% for
rules-only), all small rewrites with the words' meaning kept ("lol ok" -> "Lol, okay.",
"2:30 PM" -> "2:30pm", "No, no, I did not say that." -> "No, I did not say that."). It also
needs a 462 MB download and about 1.0 GB of RAM at a 2k context (1.7 GB at 8k).

Because the restraint cost is real and the suite is small (0 losses in 188 means the true rate
could still be up to about 1.6%), the model should be an opt-in download, with rules-only as the
default and the fallback for every timeout, error or guard reject. Nothing in this PR wires
either step into dictation; a later workstream does.

SpeakoFlow Mini scored better on restraint (95.5%) but lost content in 2 cases even with the
guard (it deleted "I mean what I said:" and "I think we should"), so it fails the bar.

S1-mini's "55% content damage" did not reproduce. Without the guard and fed the raw text, it lost
a content word in 4 of 188 cases (2.1%), against 3 (1.6%) for SpeakoFlow Mini. The S1-mini card
says the control line and system prompt are required and `--reasoning-budget 0` must not replace
`enable_thinking: false`; a run that skips either is not measuring the model as documented. We
cannot see SpeakoFlow's setup, so we can't say which it did.

## What ran

- **Rules** (shipped in this PR): `Sources/UsefulVoiceCore/Formatting/CleanupRules.swift` and
  the rule-for-rule mirror `windows/src/core/formatting/cleanupRules.ts`. The eval bundles the
  TypeScript file with esbuild and runs it, so it measures the shipped code. Both cores pass the
  same 90 fixture rows (`evals/cleanup/fixtures/rules.json`).
- **Guard** (shipped): `CleanupGuard.swift` / `cleanupGuard.ts`. Rejects a model output with a
  `<think>` tag, an empty output, an output over 1.5x the input plus 16 characters, an output
  with exactly the input's words (format-only edits), more than 15% of the input's content words
  dropped (50% when the input has a self-correction cue such as "no wait", "sorry", "I mean"),
  or new content words beyond 10% of the output's. A reject keeps the rules-only text.
- **Control line** (shipped): `CleanupControlLine.swift` / `cleanupControlLine.ts`, the S1-mini
  vocabulary quoted from its card (revision `34add00a`). Styling is the user's style if it is one
  of the four trained values, otherwise `semi-formal`; Context is `email` for email apps,
  otherwise `general`; Structure is always `prose`.
- **Cases**: `evals/cleanup/cases.json`, 188 hand-written English cases in the shape Deepgram smart
  format returns (punctuated, cased): 88 already clean (47%), 22 filler, 12 stutter, 24
  self-correction, 14 spoken format (emails, URLs, numbers, times), 6 email dictation, 16
  coding-agent prompts, 6 file mentions. Each has an expected text and accepted alternatives,
  an app category, and a dev/test split by SHA-1 of the id (91 dev, 97 test).
- **Runner**: `evals/cleanup/run_eval.py` starts one `llama-server` per model and sends every case
  through the OpenAI-style chat endpoint, one at a time.

### What the models got wrong

Rules + S1-mini + guard, the 8 clean texts it changed: "It was, like, really cold outside, you
know?" lost "like"; "She had had enough" became "She had enough"; "No, no, I did not say that."
lost one "no"; "lol ok" became "Lol, okay."; "due on 12 March" became "due on March 12" (and an
Oxford comma); "555-0123 after 4:30 p.m." became "5550123 after 4:30pm"; "2:30 PM" became
"2:30pm"; "9 a.m. on Monday; please" became "9am on Monday. Please". Its edit misses include one
real error the content metric does not count because it is digits: "five five five, oh one two
three" became "50123". Two misses are only format variants the expected list did not foresee
("2:30pm" for "2:30 p.m.").

Rules + SpeakoFlow Mini + guard lost content twice: "I think we should, uh, wait until Monday."
became "Wait until Monday." and "I mean what I said: the plan needs a second review." became "The
plan needs a second review." It also turned a clean "First, ... Second, ... Third, ..." into a
numbered list, dropped "that that" to "that", and dropped "you know?". It reformats email
dictation into greeting and sign-off blocks with no control line asking for it. It barely
formats spoken numbers (28.6%), which its card says is the rules layer's job.

Without the guard, S1-mini's content losses were all real: it split the identifier
`useLayoutEffect` into "use LayoutEffect" (twice), dropped "Uh-huh", and rewrote "gonna" as "I'm
going to". The guard caught all four.

### The guard

Of S1-mini's 188 outputs the guard rejected 130: 126 because the output had exactly the input's
words (format-only, so the rules text is the same words anyway) and 4 for dropped content. Of the
130, 110 were outputs that matched the expected text, almost all clean or rules-fixed cases where
the model returned the rules text unchanged, so rejecting them changes nothing. For SpeakoFlow
Mini: 141 no-word-change and 1 dropped-content reject.

The limits were set before the first run and not tuned. Two changes were made after reading the
first run, and both runs are kept (see Raw files):

1. The no-word-change check. In the first run, S1-mini (`semi-formal`) + guard without it had
   80.7% restraint (Oxford commas, "Lol, okay.", recased path components like
   `C:\Users\Wasim`); the same configuration with it has 90.9%. The check is a
   rule about what the model is for (Deepgram already formats), not a fitted threshold.
2. "point" and "p m" added to the guard's spoken-symbol words. Before, every spoken decimal
   ("two point five" -> "2.5") and spoken time was rejected as dropped content. Together with the
   accept-list change below, S1-mini + guard went from 92.0% restraint and 88.0% edit accuracy to
   90.9% and 94.0%; content loss stayed 0.0%.

Three expected lists gained the rules' own output (an orphan comma after a deleted filler, as
other cases already accepted) after the first run.

S1-mini's 8k figure is the KV cache; dictation needs well under 2k tokens.

## Conclusion and what changed

- `CleanupRules`, `CleanupGuard` and `CleanupControlLine` ship in the core (Swift and TypeScript),
  not wired into dictation yet. The rules are safe to wire in now: 100% restraint, 0% loss, and
  they fix every filler and stutter case.
- Recommendation for the wiring workstream: rules always; S1-mini (Q4_K_M, revision above) as an
  opt-in download with `CleanupGuard` and a strict time limit, the rules text on any reject,
  timeout or error. Run it with `-c 2048`. Credit it as "S1-mini" by "Superwhisper".
- SpeakoFlow Mini is not recommended: it lost content even behind the guard.
- If restraint must stay at 100%, ship rules-only and keep S1-mini behind a hidden flag; the
  numbers above are the trade.
